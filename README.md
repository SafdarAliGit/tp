### Tp

Front-end portal for **tp.cx** (Towel Production on Frappe 16 + ERPNext).
Plain JavaScript (ES modules, no build step), design-token CSS and a small whitelisted Python API.

#### Routes

| URL | Page |
| --- | --- |
| `/login` | Sign in (replaces Frappe's login page) |
| `/` | Dashboard |
| `/contracts`, `/contracts/new`, `/contracts/<name>` | Weaving Contract Terry list and form |
| `/items`, `/customers`, `/colors` | Master data (list + drawer form) |

The Frappe desk stays at `/desk`.

#### Access control: Page Access

Each portal page has a **Page Access** record (Desk → Page Access, or *Page Access* in the portal sidebar for System Managers).
A user can open a page when:

1. the record is **Enabled**,
2. the user has **one of its Roles** (any Frappe/ERPNext role; Administrator always passes), and
3. if **Reference DocType** is set, Frappe grants the user `read` on it.

Create / edit / delete inside a page always follow the DocType's own Frappe permissions.
Records are created on install/migrate from `tp/config/pages.py` and are never overwritten, so changes made in the desk are kept.

#### Project layout

```
tp/
├── access.py              # page access rules (roles + DocType permissions)
├── portal.py              # shared context for www pages, asset versioning, home page hook
├── config/
│   ├── pages.py           # page registry (seeds Page Access)
│   └── resources.py       # master-data list/form definitions
├── api/                   # /api/method/tp.api.*
│   ├── contracts.py  dashboard.py  resources.py  search.py  session.py  utils.py
├── setup/install.py       # after_install / after_migrate seeding
├── tp/doctype/            # Page Access, Page Access Role
├── templates/tp/          # shell.html, resource.html, head.html, macros.html, icons.html
├── www/                   # portal pages (login, index, contracts/, items, customers, colors)
└── public/
    ├── css/  tokens.css → base.css → components.css → layout.css → pages.css
    └── js/
        ├── app.js         # shell: sidebar, menus, theme, Ctrl+K palette
        ├── core/          # api, dom, format, toast, overlay, theme
        ├── components/    # data-table, form, grid, link-field
        ├── lib/           # contract-calc (mirrors the DocType controller)
        └── pages/         # one module per page
```

JS modules import each other as `@tp/<path>.js`. An import map generated by `tp/portal.py` versions each file by its mtime, so browsers never serve stale modules.

#### Adding a master-data page

1. Add the page to `tp/config/pages.py`.
2. Add a resource to `tp/config/resources.py`.
3. Copy `tp/www/items.html` + `items.py` and change the key.
4. Run `bench --site tp.cx migrate` to create the Page Access record.
